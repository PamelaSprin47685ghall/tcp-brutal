状态：G2 证据包。分支 `w-fec-v6`，基线 `master 0db5166`。
接口契约：`review/goal-v6-interfaces.md`（T0，head `2372a03`，ABI 未变）。
实现说明：`review/fec-v6-wire.md`。

## 1. 已落地

### 1.1 FEC v6 wire（`tbtun/tbt_fec.c/h`）

- 40 B 小端 header：`+32 payload_crc32c`（仅 payload）、`+36 header_crc32c`（覆盖 +0..+35）。`pack/unpack` 是 wire 权威，不直接写结构体。
- RX 顺序：`conv/type/长度` → `header_crc32c` → 字段语义 →（DATA/PARITY 解密）→ `payload_crc32c`。header/framing 失败关 carrier；payload CRC 失败只丢记录。
- DATA `payload_len` 1..S，短包必须 `flags.LAST`；PARITY 恒 S；DATA share 索引 < n，PARITY 在 [n, n+m)。
- 控制帧：ACK 16 B、NACK 12 B/项（≤64 项/768 B）、FEC_CFG 32 B（内部 CRC）、FEC_FBK 48 B（16 B 字段 + 32 B bitmap）。256-bit bitmap 独立，不复用 `path_ack_mask`。
- 控制帧只允许在记录边界写入；`tbt_carrier_send()` 部分写返回 `-EIO`，调用方整记录重试/丢弃，不插队。

### 1.2 256 carriers / 旧 ARQ 隔离

- `TBT_MAX_CARRIERS_LIMIT=256` 只给载体槽/新 FEC；`TBT_LEGACY_MAX_CARRIERS=16` 用于 `path_id/path_ack_count/path_ack_mask`、FBK/WINDOW 边界、旧测试。旧 wire 字节不变（`TBT_FBK_MAX=288`、`TBT_WINDOW_BODY_LEN=138`）。
- `max_carriers` 默认 256；`carrier_sockbuf_kib` 默认 64；`carrier_buffer_budget_mib` 默认 128。
- 模块级预算：`atomic64_add_return` 后比较、超限回滚；`s->buf_kib` 在 destroy/创建失败路径减回。
- 默认全局端口块 40000–44095（4096）。`tbt_portmap.c/h` 是 host/kernel 双编译的纯位图分配器；`tbt_port_alloc/free` 在 mutex 下调用它。
- session 级 50 ms poll：一个 `sess->w_poll` 遍历 `car[0..n_car-1]` 和 prov 列表；删除 per-carrier `w_poll`。`state_change` 用 `mod_delayed_work` 提前唤醒；`carriers_stop`/destroy 双取消。
- `tbt_replace_work` 的两个 256 指针数组改堆分配，消除 4 KiB 内核栈 frame。

### 1.3 Host RLNC / grouped codec

- 单组 GF(2) 滑窗 RLNC；`d=w`（w>1）拒绝；`d=w/2` 生产。
- grouped：`groups ≤ 256`，每组独立 ctx；`group = seq % G`；`group(carrier)=c/(n+m)`，`share(carrier)=c%(n+m)`；`block_id=(seq/G)/k`。
- 动态参数：p≤1% M=3/N=5/W=10/d=5；≤20% M=4/N=4/W=8/d=4；≤30% M=5/N=3/W=6/d=3；>30% M=6/N=2/W=4/d=2。single 256 仅 p≤20%（M=64/N=192/W=384/d=64）。
- `struct tbt_fec_ops` + `tbt_fec_ops_rlnc`；`TBT_FEC_CODEC_SC_LDPC` 保留给 D，`params_check` 当前拒绝。
- 分配可能睡眠：codec 创建/释放只能在进程上下文；bind 后每包路径不分配。

### 1.4 Parser / procfs

- 新键：`fec=off|on`、`mode=rlnc|grouped|sc-ldpc`、`w=0..1024`（0=auto→2n，sc-ldpc→256）、`carriers=0..256`（0=auto=n+m，须整除）。
- canonical 顺序：`... profile= fec= mode= w= carriers= keepalive= ...`；0 解析为 effective 值后渲染定点，回环稳定。
- `fec=off` 且 `n+m>16` 拒绝，文本 `legacy ARQ supports n+m<=16; set fec=on for 256 carriers`。
- `fec=on` 在 `tbt_session_create()` 返回 `-EOPNOTSUPP`（数据面未合入）；parser/procfs 接受并渲染 256 行。
- `fec=on` 时 `dup/replay/max_inflate/hole_budget_ms/rx_reorder_bytes/tx_retain_bytes` 继续解析/渲染，FEC 数据面不读；`dup` 绝不在 FEC 路径复制 DATA/PARITY。
- `ports lo-hi` 全局块渲染不变；`tbt_portmap_set` 用 `tbt_portmap_words()`，4096 端口不截断。

## 2. T0 §9.2 跟踪项确认

1. **grouped/block_id**：`group(carrier)=carrier/(n+m)`、`group=seq%G`、`block_id=(seq/G)/k`（组内 generation，不编码 group、不做 stream demux）。不改 wire；host 测试覆盖 256 carrier 边界与单调性。
2. **旧 16 槽拆分**：旧 ARQ 全部用 `TBT_LEGACY_MAX_CARRIERS=16`；`TBT_MAX_CARRIERS_LIMIT=256` 只给载体槽/新 FEC；`n+m=256` 不截断，`fec=off` 的 `n+m>16` 被拒。
3. **末包**：DATA `payload_len` 1..S + `flags.LAST`；PARITY 恒 S；host 测试覆盖短包/非 LAST 拒绝。
4. **w=/carriers= auto**：0 解析为 effective（2n / n+m），golden 行同步，回环逐字节稳定。
5. **legacy 键**：解析/渲染但 FEC 数据面不读；`dup` 不在 FEC 路径复制。当前 FEC 数据面被 `-EOPNOTSUPP` 挡住，因此没有可触发的复制路径。
6. **全局 ports**：默认 4096；`host/test_portmap` 在 30000–34095 上连续 alloc 256、free 再 alloc 256，并覆盖 4096 位图、1024/64 端口块、耗尽/重复释放。
7. **crypto 边界**：FEC header/CFG/FBK 不含 key/nonce；key 走 HELLO v6 body。每端 TX 用自己的 8 B crypto_nonce，RX 用对端 nonce；session 两个 ctx。TX `seal(明文)→body_xor`，RX `body_xor→verify`；控制帧跳过。B 不实现 HELLO/crypto ctx。

## 4. 已知限制 / 交接

- `fec=on` 只到解析/渲染；内核 FEC 数据面未合入（等 A 的 N=1 修复与 T0 冻结后的集成窗口）。`-EOPNOTSUPP` 是诚实闸门，不是占位实现。
- `DESIGN.md` 仍写 16 carriers/40000-40063；本分支不改该文件，T0 文档是 v6 权威。
- 模块级 128 MiB 预算的并发单元场景在旧 ARQ 16 槽上限下无法构造（FEC 会话被闸门挡住）；预算代码路径已按 add-then-compare 实现，等 FEC 数据面落地后由集成测试覆盖。
- 256 carrier 的 live QEMU 未跑：slirp 单线程不适合；生产验证留给 HND0/真实 WAN。
- **A**：本分支未改 `tbt_tx.c/tbt_rx.c`；`TBT_MAX_CARRIERS_LIMIT` 变 256 只影响数组尺寸，旧 ARQ 仍 16 槽。合并顺序 A→B。
- **C**：整记录写入/控制帧不插队；crypto 钩子按 §2.4/§2.5；FEC_CFG 32 B 不变。
- **D**：`TBT_FEC_CODEC_SC_LDPC` 与 `tbt_fec_ops` 形状已留；`params_check` 当前拒绝 SC-LDPC，D 接入时补实现，不改 40 B header。
