# 0.4.2 数据面 ChaCha8：4-block 交错在 -mno-sse 下无效

服务于 `t-04x-perf`，基线 master `5192dd0`，评估分支 `w-0.4.2-crypto`。

## 结论

1. 内核编译本文件时确实禁用 SIMD：`tbtun/.tbt_crypto.o.cmd` 为
   `-O3 -mno-sse -mno-sse2 -mno-mmx -mno-avx`（`CFLAGS_tbtun/tbt_crypto.o := -O3`
   叠加 kbuild 约束），通用寄存器只有 15 个可用。
2. 纯 C99 4-block 交错（`x[word][lane]`，lane 内层，256 B 步长）在 `-O3`（允许
   SSE）下被 GCC 16.2.1 SLP 向量化：1191 → 2477 MB/s（2.08×）。内核拿不到。
3. 在 `-mno-sse` 下 4-lane 相对"单块融合"没有可测优势；收益来自融合，不是交错。

## 方法

- 密码核心：`host/bench_crypto`，8192 B、8 轮、每格三次取中位。内核态等价物是
  同一 `tbt_crypto.c` 用 `-O3 -mno-sse -mno-mmx -mno-sse2 -mgeneral-regs-only`
  单独编成 .o 再链接，唯一区别是头文件分支。
- 数据面入口：夹具反复调 `tbt_crypto_body_xor_flow(ctx, sid, seq, false, 0,
  buf, 8192)`（同 `tbt_crypto_xor_at`，与实际 share 同路径），每次 4000 share、
  五趟取最小，再跨版本交替取最小。
- 机器共享，单次波动 ±5%；跨会话绝对 MB/s 不可比，比值可比。gcc 16.2.1，约 4.6 GHz。

## 数据（8 KB payload，内核标志）

| 版本 | bench_crypto MB/s（受负载影响） | share 入口 µs/share（同窗交替） |
|---|---|---|
| 旧：单块 + 64 B 缓冲 + tbt_xor_bytes | 1381–1619 | 5.59–5.78 |
| 4-lane 交错（也做了融合异或） | 1536–1664 | 5.11–5.22 |
| 单块融合（采用） | 1443–1691 | 4.95–5.20 |

`-O3`（SSE）同一 bench：旧 1191–1303，4-lane 2477，单块融合 1502–1527。

bench_crypto 的区间互相重叠：同一对二进制在不同负载下给出 +3%～+16%，频率与
缓存状态淹没差异，不能用来判定。share 入口是同窗交替测的，才是判据：旧 5.59 →
采用 4.95（−11.5%），六轮典型 −8%；4-lane 落在 5.11–5.22，与本改动在噪声内相
当。每 share 纯 CPU 按 profile 的 8.9 µs 计约 −7%，按 7.5 µs 计约 −8%，均达
≥5% 的目标。

## 为什么 4-lane 在内核态不划算

- 4 块 × 16 字 = 64 个活跃 u32，15 个通用寄存器装不下，中间量必然落栈，每轮
  32 个 quarter-round 的调度空间被 spill/restore 吃掉。
- u64 打包是 32 位 CPU 的技巧：2 块要 16 个 u64 再加临时量，仍放不下；且 lane
  内 rot16/rot8 需跨 lane 屏蔽，每条从 2 条指令变 4–5 条。数学上不成立。
- 4-lane 代码 16 KB（单块 4.7 KB），L1i 压力换不到速度。内核要用 SIMD ChaCha
  只能走 crypto 子系统的 asm + kernel_fpu_begin，不在本仓库的纯 C99 范围内。

## 采用的改动与验证

`tbt_chacha8_block_xor()`：置换后直接 `x[i] + state[i]` 并异或进 payload，整块
不再落地到 64 B keystream 缓冲，也不再多一次 `tbt_xor_bytes`；只有不足 64 B 的
尾块仍走 `tbt_chacha8_block()` + 缓冲。`tbt_memzero()`（volatile 逐字节）取代
可被 DSE 消除的 `memset` 擦尾块。

- `test_bulk_kat`：512 B（8 块）两侧入口对钉死向量，前 128 B 即公开的
  `test_generated_256` 向量；向量取自 5192dd0 旧实现并与公开向量吻合。
- `test_length_sweep`：长度 1..320 逐一对该流前缀，流式与绝对入口都测。
- `test_counter_wrap` 增补 128 B 与 `xor_at` 129 B 的 2^64 边界行为。
- `-O2`、`-O3`、`-O3 -mno-sse` 三种构建输出逐字节相同；`make check` 与
  `make host-test-san` 全绿；栈帧 192–224 B（`-fstack-usage`）。

## 复现

```
make host-bench-crypto                      # 允许 SSE 的一侧
cc -O3 -std=gnu99 -mno-sse -mno-mmx -mno-sse2 -mgeneral-regs-only \
   -I tbtun -c tbtun/tbt_crypto.c -o /tmp/c.o
cc -O3 -std=gnu99 -I tbtun -o /tmp/bench host/bench_crypto.c /tmp/c.o tbtun/tbt_proto.c
```
