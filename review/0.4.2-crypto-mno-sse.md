# 0.4.2 数据面 ChaCha8：4-block 交错在 -mno-sse 下无效

服务于 `t-04x-perf`，基线 master `5192dd0`，评估分支 `w-0.4.2-crypto`。

## 结论

1. 内核编译本文件时确实禁用 SIMD：`tbtun/.tbt_crypto.o.cmd` 为
   `-O3 -mno-sse -mno-sse2 -mno-mmx -mno-avx`（`CFLAGS_tbtun/tbt_crypto.o := -O3`
   叠加 kbuild 约束），通用寄存器只有 15 个可用。
2. 纯 C99 4-block 交错（`x[word][lane]`，lane 内层，256 B 步长）在 `-O3`（允许
   SSE）下被 GCC 16.2.1 SLP 向量化：1191 → 2477 MB/s（2.08×）。内核拿不到。
3. 在 `-mno-sse` 下 4-lane 落后于融合形态（share 入口 5.09 对 4.31 µs）；收益来自
   融合与循环结构，不是交错。
4. P2-1 擦除若按字面每块擦 `x[16]`，16 次 volatile store 加屏障吃掉全部收益
   （5.52–5.66 µs，同窗旧 5.55）；擦除放到整段 run 的出口（契约不变）反而最快。

## 方法

- 密码核心：`host/bench_crypto`，8192 B、8 轮、每格三次取中位。内核态等价物是同
  一 `tbt_crypto.c` 用 `-O3 -mno-sse -mno-mmx -mno-sse2 -mgeneral-regs-only`
  单独编成 .o 再链接，唯一区别是头文件分支。
- 数据面入口：夹具反复调 `tbt_crypto_body_xor_flow(ctx, sid, seq, false, 0,
  buf, 8192)`（同 `tbt_crypto_xor_at`，与实际 share 同路径），每次 4000 share、
  五趟取最小，再跨版本交替取最小。
- 机器共享，单次波动 ±5%；跨会话绝对 MB/s 不可比，比值可比。gcc 16.2.1，约 4.6 GHz。

## 数据（8 KB payload，内核标志）

| 版本 | share 入口 µs（同窗最小） | 相对同窗 old |
|---|---|---|
| 旧：单块 + 64 B 缓冲 + tbt_xor_bytes | 5.11 | — |
| 4-lane 交错（也做了融合异或） | 5.09（同窗 old 5.36） | −5.1% |
| 每块调用的融合单块（P2-1 前） | 4.68（同窗 old 5.11） | −8.4% |
| 整段 run + 出口擦除（采用） | 4.31（同窗 old 5.11） | −15.6% |

同一窗口 bench_crypto（内核标志）：1606.5 → 1829.8 MB/s（+13.9%）。该 bench 的
比值受负载影响（同一对二进制曾给出 +3%～+16%），只作旁证；`-O3`（SSE）同一
bench：旧 1191–1303，4-lane 2477，融合 1502–1527。

share 入口是同窗交替测的，才是判据：旧 5.11 → 采用 4.31（−0.80 µs）。每 share
纯 CPU 按 profile 的 8.9 µs 计约 −9%，按 7.5 µs 计约 −11%，均达 ≥5% 的目标。

## 为什么 4-lane 在内核态不划算

- 4 块 × 16 字 = 64 个活跃 u32，15 个通用寄存器装不下，中间量必然落栈，调度空间
  被 spill/restore 吃掉；4-lane 代码 16 KB（单块 4.7 KB）。
- u64 打包是 32 位 CPU 的技巧：2 块要 16 个 u64 再加临时量，仍放不下；且 lane 内
  rot16/rot8 需跨 lane 屏蔽，每条从 2 条指令变 4–5 条。数学上不成立。
- 内核要用 SIMD ChaCha 只能走 crypto 子系统的 asm + kernel_fpu_begin，不在本仓库
  的纯 C99 范围内。

## 采用的改动与验证

`tbt_chacha8_blocks_xor()`：整段 share 一次调用，置换后直接 `x[i] + base[i]` 异或
进 payload；计数器放进局部 u64（在 `st[]` 里逐块自增会让 RMW 落在循环关键路径
上：4.96 对 4.28 µs）。出口一次擦除 `x[16]` 与 `base[16]`——两者都是每块复用的
同一栈槽，擦最后一次即覆盖全部残留。不足 64 B 的尾块仍走 `tbt_chacha8_block()`
+ 缓冲。`tbt_crypto_xor_at()` 改单出口，同时擦 `st[16]`（密钥调度副本）与
`block`；擦除统一走 `tbt_crypto.h` 的 `tbt_memzero_explicit()`，与 `f96f9f0` 对齐。

- `test_bulk_kat`：512 B（8 块）两侧入口对钉死向量，前 128 B 即公开的
  `test_generated_256` 向量；向量取自 5192dd0 旧实现并与公开向量吻合。
- `test_length_sweep`：长度 1..320 逐一对该流前缀，流式与绝对入口都测。
- `test_counter_carry_bulk`：0xFFFFFFF0 起 65 块（4160 B）跨低字进位，两侧一致，
  且 0x100000000 起 49 块与前者偏移 16 块逐字节相同。`test_counter_wrap` 另测
  128 B 与 `xor_at` 129 B 的 2^64 拒绝点。
- `-O2`、`-O3`、`-O3 -mno-sse` 三种构建输出逐字节相同；`make check` 与
  `make host-test-san` 全绿；栈帧 192–400 B（`-fstack-usage`）。
